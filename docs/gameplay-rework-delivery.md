# 玩法返工交付（2026-09-10）：取消孤子不死 / 多颗落子 / 死亡宽限 / 棋子攻击

> 状态：**已发布上线** · 版本 `client.js?v=20260912c`
> 验证：`npm test` **249/249** · 独立 QA 探针 **81/0 PASS**（复验两轮）· go 探针 72/0 · 封禁 32/32 · 房间端到端 28/28

## 1. 用户需求（逐字）

> 1. **取消两个模式的孤子不死**
> 2. **回合制模式改为一回合可以下多颗棋子，这个数量可以自己设置，不设置的话默认为构建一个可以存活的最小单位所需要的棋子数**
> 3. **可以设置死亡回合，也就是可以设置孤子这种无法永久存活的单位一回合、两回合或者 n 回合后才会触发死亡（默认的话就是原来的 0）**
> 4. **实时模式中，棋子实际上是原始细胞产生的细胞，按理来说也应该会攻击才对**
> 5. （追加澄清）**回合制下一名玩家下完多颗棋子在点完点击结束回合后棋盘才会开始运行，在点击结束回合前下错了可以撤回**

## 2. 定案的参数与设计

| 项 | 决定 | 理由 |
|---|---|---|
| 每回合落子数 | 默认 **3**，可设 1..16 | 康威规则下"可存活的最小单位"= 3 颗（三颗 L 形会塌成 2×2 方块；直线三连是永不灭亡的闪烁器） |
| 死亡宽限 | 默认 **0**，可设 0..10 | 0 = 立即死 = 用户说的"原来的 0" |
| 棋子攻击形态 | **近战吞噬**（格子对格子磨血） | 用户原话是"棋子…应该会攻击"，在生命棋盘语境下即为相邻格互攻 |
| 落子节奏 | **批次 = 结束回合**（不新增协议字段） | 用户第 5 条：点【结束回合】后棋盘才开始运行 |

## 3. 冻结接口契约

- `World` opts：`stonesPerTurn`(1..16, 默认 3) / `lonelyDeathDelay`(0..10, 默认 0)
- `World` 常量：`STONES_PER_TURN_DEFAULT/MAX`、`LONELY_DEATH_DELAY_DEFAULT/MAX`、`CELL_ATK_HP = 3`
- 快照：`snapshot().settings = { stonesPerTurn, lonelyDeathDelay }`；`snapshot().lifeHits = [[x,y,dmg],...]`（稀疏）；`snapshot().go.stonesPerTurn / .stonesLeft`
- go 意图：`{ go: { moves: [{lx,ly},...] } }`（兼容旧 `{go:{lx,ly}}`）；返回 `{ok, placed, captured}`；新增 reason `too_many_stones`

## 4. 核心机制

### 4.1 取消孤子不死（两种模式）
rts 的 `_lifeStep` 与 go 的 `_goEvolveOnce` 统一为**标准康威 B3/S23**：`n === 2 || n === 3` 才存活（强/弱细胞同一套判定）。保留"本回合刚落的子当回合豁免"（≠ 永久不死）。

### 4.2 死亡宽限（`lonelyDeathDelay`）
新增 `_lifeDoom` 网格（`-1` = 尚未获得宽限，`>= 0` = 剩余宽限回合）：

```js
if (!alive) {
  let d = doom[x][y];
  if (d < 0) d = this.lonelyDeathDelay;   // 首次失败才发放宽限（delay=0 → 立即死）
  if (d > 0) { alive = true; doomNext = d - 1; }
  else { doomNext = -1; }                  // 宽限耗尽 → 死
} else { doomNext = -1; }                  // 恢复健康 → 清零
```

实测语义：`delay=0 → [0,0,0]`；`delay=1 → [1,0,0]`；`delay=2 → [1,1,0,0]`。

> **易错点**：必须用 `-1` 区分"尚未发放"与"已耗尽"。若用 `0` 兼作哨兵，`delay >= 1` 会**永远死不了**。

### 4.3 实时模式：棋子近战吞噬
每 `_lifeStep` 一拍（仅与演化同拍，非每 tick）：
- 相邻**敌方弱痕** → 直接吞噬（`cell_eaten`）；
- 相邻**敌方强细胞** → 累积伤害 `dmg += max(1, atkIn)`，`dmg >= killAt` 击碎，其中
  `killAt = Math.ceil(CELL_ATK_HP(3) × resist × anchor)`，`anchor` = 2（在 2×2 要塞内）否则 1；
- 无攻击者时自愈 `dmg - 1`。

阈值随 resist **单调**变化：`1.0→3 / 1.15→4 / 1.5→5 / 2.0→6 / 3.0→9`（要塞内翻倍）。

> **两个已修的坑**：① 原用 `block = Math.floor(resist)` 做减伤 → **resist 1.0~1.99 无任何减伤**，导致纪元 `resist=1.5` 与「膜增厚 +0.15」在近战上完全无效（玩家拿到升级感觉不到）。改为阈值缩放后消失。
> ② 原为"边累加边就地清除" → **1v1 贴脸时结果由棋盘坐标 (x,y) 决定**（下标小者先被清，另一方当拍失去攻击者而自愈存活）。改为**两阶段结算**（2-A 只计算、2-B 统一清除）→ **同拍互灭**，并加了"顺序无关性"测试锁死。

### 4.4 回合制：多颗落子 + 结束回合
- 客户端点棋盘**只入预选草稿**，棋盘**不演化**；点【结束回合（k/N）】才整批提交。
- **撤回**：左键点已预选幽灵子取消那一颗；右键/Esc 撤最后一颗。
- 服务端结算：整批原子校验 → 一次性落子 → 统一结算提子（**把这一批当成整体判自杀**）→ **演化一次** → 换手。
- **倒计时保护**：服务端 30s 超时是服务端自己 pass（看不到客户端草稿），故客户端在本地倒计时**剩 2 秒**时抢提交已预选批次，避免玩家白下。

## 6. 本轮修掉的既有缺陷（非用户直接要求）

1. **私密房房名泄漏**（前一轮）：`GET /rooms/:code` 私密分支返回 `name`，与其注释及 `/rooms/search` 策略矛盾。
2. **文案与引擎不符**（多处，且部分是**历史遗留**）：
   - go 速查「目标」写"落一子"而「规则①」写"可落多颗" —— 同弹层自相矛盾；
   - 按键面板写「F 种 **2x2** 强细胞团」、落子飘字「**+2x2 据点**」，而引擎每次 F **只落 1 格**；
   - "要 2×2 或**连片**才稳" —— 2 颗相邻也死，该说法在边界处为假。
3. **`GET /worlds/:id` 静默重置房间设置**：未传 roomOpts → 把玩家设的 9/5 悄悄改回 3/0，**并把默认设置的世界缓存进 `activeWorlds`** 污染后续进房。
4. **DB 引擎选择顺序**（前一轮）：`initDB()` 先选引擎后建目录 → 全新文件系统首启会静默落到 `sql.js`（WASM、5s 落盘）。
5. **DB 持久化**（前一轮）：原先未设 `DB_PATH` → 默认 `:memory:` → 重启即丢全部账号。

## 11. 追加需求：结束回合支持「不落子 / 少落子」（已上线 `?v=20260912d`）

> 用户原话：**"另外，也可以选择不落字或者少落子，直接点击结束回合"**

### 原实现为什么做不到（主理人核出的真缺口）
`public/client.js` 三处联合把这个用法堵住了：
1. `submitGoPending()` 首行 `if (!state.goPending.length) return false` → **0 颗直接不发送**；
2. 按钮渲染 `canSubmit ? '' : ' disabled'` → 0 颗时按钮**是灰的**；
3. 点击处理器 `toast('先点击棋盘预选落子，再点【结束回合】')` → **把正确用法说成错误用法**。

结果：0 颗时只能绕道点独立的 `Pass` 按钮。

### 修法
- `submitGoPending()`：去掉"至少 1 颗"的限制；**`k === 0` → 发 `{go:{pass:true}}`**，否则发 `{go:{moves}}`（1..N 任意，无"必须摆满"校验）。
  ⚠️ **0 颗绝不能发 `{go:{moves:[]}}`** —— 服务端判 `bad_move`。
- 按钮：删除 `canSubmit` 与 `disabled`/灰化，**任何数量都能点**；文案自适应 `结束回合（不落子）` / `结束回合（k/N）`。
- 删除误导 toast；`Pass` 按钮**保留**（Go 玩家熟悉该词），两者 k=0 时**发同一意图**。
- `sec<=2` 抢提交**保持不变**：仅 `goPending.length > 0` 时抢提交，0 颗绝不替玩家 pass。
- 文案补充：「不落子也可以直接点【结束回合】= 停一手；少于上限也能随时结束回合」。

### 实测（真实服务 + WS）
```
少落子 1/3        → 被接受，moveNo 1→2，lifeGrid[10][10]=1（真的落下去）
不落子 pass       → 被接受，触发终局 pass（1 席时一次 pass 即终局，符合"全员各 pass 一次"）
moves:[]          → 服务端判 bad_move（客户端已规避）
实测 6/6    ·    npm test 249/249
```
