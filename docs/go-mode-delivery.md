## TL;DR

在原有实时生存模式之外，**新增一个独立并存的回合制围棋模式**：一个 32×32 棋盘、只有玩家/电脑玩家两方、自由落子、无强弱棋子之分、靠先后拓展定领土，**每回合落子后全盘跑一步康威生命游戏演化**，让自己长出去抢地。

**`npm test` 183/183（实时模式零回归）· go 模式测试 23/23 · 7 个源文件语法全过 · 真实双人邀请对弈链路实跑通过。**

## 一、用户需求 → 实现映射

| 用户原话 | 实现 |
|---|---|
| "只有一个棋盘" | 32×32 单棋盘，复用 `lifeGrid` 渲染（客户端零成本） |
| "只有玩家/电脑玩家没有其它乱七八糟的单位" | go 世界不生成任何涌现单位、无资源、无地形、无潮汐；UI 隐藏全部 rts 面板 |
| "落子位置可自由选定位置" | 任何空点均可落，不限于邻接 |
| "没有强弱棋子的区分" | 棋盘只写 `0/1/2`，**绝不写 `11/12` 弱痕段**（QA 60 手随机对局扫描验证零泄漏） |
| "以先后拓展位置来决定哪个抢占领地" | 落子 = Voronoi 种子，每回合演化向外长；领地边界有独立描线 |
| "类似围棋" | 正统围棋吃子：**4 邻气 + 禁自杀 + 劫**（问卷选定的"正统围棋吃子"） |
| "每回合演化类似康威生命游戏" | 落子 → 提子 → 康威 B3/S23 一步；**刚落的子豁免死亡**（避免"落下即死"挫败） |
| "你也可以优化一下规则，但是不要太复杂" | 8 条规则一屏讲完；终局 5 条件；超时=自动 pass |
| "别忘了算法，还有那些类似康威生命游戏的一些不可预测的数学的东西" | **四个种子化不可预测源**（见下） |
| 单局时长（问卷"标准 ~15 分钟"） | 30s/手上限、150 手上限、目标均值 6s/手 |

### "不可预测的数学"四源（全部走种子化 RNG，禁 `Math.random`）

| 机制 | 周期 | 玩家感知 | 实测 |
|---|---|---|---|
| 影响半径呼吸 `markov_chain` | 每 10 手 | 领地边界整体涨潮/退潮 | R ∈ {3,4,5} 三档均出现 ✅ |
| 世界事件 `markov_chain` | 每 25 手 | 繁盛/寒潮/拥挤突变，节奏可预期内容不可预期 | 四态全出现 ✅ |
| 图案奖 | 持续 | "会行走的图案"+5 目、"振荡图案"+2 目，把混沌变成可追逐的正反馈 | 归属正确 ✅ |
| 康威演化本身 | 每手 | 边界长出珊瑚/迷宫状结构 | 确定性可复现 ✅ |

## 四、过程中发现并修复的问题（按严重度）

| # | 严重度 | 问题 | 根因 |
|---|---|---|---|
| 1 | 🔴 崩溃 | **两个真人一落子，服务进程退出** | 踢 AI 时未回收 `_lifeOwners` 槽位 → 第 2 人类拿到 faction 3 → `go.js` 写死的 `sigs={1:[],2:[]}` 越界 → 崩在 `snapshot()` 主链 |
| 2 | 🔴 功能阻断 | 邀请好友无法对弈：第 2 个人类拿不到席位 | go 房间第 1 个人类进房即被 AI 补满第 2 席 |
| 3 | 🔴 体验 | 新玩家进 go 模式首屏弹的是**实时模式教程** | 简报在登录时触发，那一刻还不知道进哪个模式 |
| 4 | 🔴 内容 | 简报教玩家按 `P`/`Ctrl+R`，但键位未实现 | 文案先行、实现漏做 |
| 5 | 🟡 设计 | "演化平票掷种子"是死代码 | bornThresh=3 时两方计数之和为奇数，恒不相等 |
| 6 | 🟡 边界 | 第 3 个人类成幽灵玩家、污染玩家列表 | `addPlayer` 无超编保护 |
| 7 | 🟡 体验 | 领地边界底色过淡，核心机制感知不到 | `0x33` 透明度太低 |

**另修正 3 处上游设计判断**：`_captureEnclosed` 不能复用（8 邻"围死"≠围棋 4 邻"气"）；`conway_life` 内核从未被调用且是环形边界（围棋需非环形）；无需给数据库加 `mode` 字段（`seed + 手顺` 即可复盘）。

## 五、最重要的一条教训

**CRITICAL-1 崩溃躲过了三次独立验证**（工程师单测 → QA 第一轮探针 → QA 第二轮回归），因为它需要同时满足：

1. 两个**真人**（触发 AI 被顶替 → faction 槽位残留）
2. **真的落一手**（空盘/单人局 faction 恒为 {1,2}，不落子永远不会崩）

**离线单测存在结构性盲区**——只有真实起服务、走完整"邀请好友"链路才撞上。

> 由此新增两条项目铁律，已写入 `MEMORY.md`：
> - `_lifeOwners` 槽位**只能置 null 复用，永不缩短**（faction 号是网格索引，不是可压缩数组）
> - 凡"删除玩家"的操作，**必须检查 `_lifeOwners` 槽位回收**

## 六、未验证项（需真人浏览器试玩）

以下在无头环境无法验证，**不算通过**：

1. 领地底色加深（`0x55`）与势力边界描线的**视觉可读性**
2. 环形倒计时的**动效与变色**（≤5s 转橙、≤2s 转红）
3. `Ctrl+R` 认输的 `confirm` 弹窗、`P` 键 2.5s 二次确认提示的**实际交互**
4. 断线暂停计时的真实断网实验（代码逻辑已确认存在）

**建议试玩清单**：
- 建 go 世界 → 首屏应弹 **go 简报**（不是"单局 30+ 分钟""WASD 移动"那套）
- 点棋盘任意空格落子 → 应有落子反馈；点已占格 / 劫点 / 自杀点 → 应留 ~1.2s 红叉 + 对应文案
- 轮到自己时棋盘有高亮边框、右上角环形倒计时在走
- 黑白分界处应有明显边界线
- 按 `P` 两次 → 停一手生效；`Ctrl+R` → 弹确认后判负
- 把邀请链接发给另一台设备/浏览器 → 两人应能**交替落子**
