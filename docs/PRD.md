## 1. 产品定位

一款**算法驱动的生存建造游戏**：程序化生成的荒野、采集与建造、科技树推进时代、生存压力（饥饿 / 昼夜 / 威胁），**单机为主**，可选择进入**实时联机房间**与他人同图游玩。

### 1.1 四条设计铁律（本次改版的根本）

| # | 铁律 | 说明 |
| --- | --- | --- |
| **1** | **主体是单机生存建造** | Minecraft 式生存 + 文明式发展：程序化世界、采集资源、建造基地、研究科技树推进时代、长期经营。**不是对战游戏、不是自走棋、没有"阵营对抗"玩法** |
| **2** | **联机是可选的实时多人** | 单人可完整游玩；玩家可创建 / 加入「世界房间」多人同图实时游玩（类似 MC 联机 / Roblox / Civ6 联机）。离线世界与联机世界同一套存档 |
| **3** | **算法是世界的法则，单位是算法的涌现** | **绝不用算法名当阵营或单位分类名**。算法是驱动世界与生物的内核；有趣的单位是算法**自然涌现**的产物（生命游戏跑出滑翔机、蚁群跑出蚁道、元胞跑出火蔓延…）。单位一律用**生态 / 生物名**命名（流萤、砂兽、蚁工、结晶、守卫…），括号里注明驱动内核 |
| **4** | **实时联机：延迟即玩法，不检测延迟** | **不做延迟补偿、不做插值预测、不测量 ping、不按客户端时间戳回溯**。指令按**到达服务器的顺序**入队，下一 tick 消费。延迟天然表现为**惯性**（详见 §1.2） |
| **3a** | **算法确定性（IR-3a）** | 同 `seed` + 同输入 → 同输出；内核为纯函数，无 `Math.random()`、无 `Date.now()`，Rng 由 seed 注入。可预测性的工程化保障。 |
| **3b** | **世界离散 tick（IR-3b）** | 玩家决策与算法评估都在 tick 边界同步；20 TPS 固定 tick；玩家 intent 在 50ms 窗口内合并为冲量。 |
| **3c** | **算法不可被玩家"读档"（IR-3c）** | 涌现识别是服务器侧；客户端只接收 `snap`；内核计算对外黑盒；客户端时间戳被忽略。 |

### 1.2 设计哲学（必须写进 README 与游戏内「关于」页）

> **延迟不是需要补偿的缺陷，而是世界中的物理量（惯性 / 质量）。**

- 服务器固定 **20 TPS** 推进世界；客户端指令是「施加**冲量**」而非「设置位置」。
- 每个实体有 `mass`（质量）与 `velocity`（速度向量）；指令只改变动量，位置由物理积分得出。
- 网络慢的玩家：冲量包到达更晚、更容易在同一 tick 内**批量累积** → 单次获得更大动量、更难急停与转向 → 表现为「**更重的球**」；网络快的玩家灵活但「轻」。
- 于是**延迟差异 = 不同质量 / 速度的球相撞**：重球撞飞轻球、轻球可绕后、群体冲撞引发连锁碰撞。碰撞结果（弹性碰撞 / 动量交换）即为玩法本身。

### 1.3 与传统生存建造的差异

| 维度 | 传统生存建造 | 本产品 |
| --- | --- | --- |
| 世界静态内容 | 手写怪物表、掉落表 | 由 46 个算法内核**涌现**；同一内核在不同地形长出不同生态 |
| 生物行为 | 脚本状态机 | 由内核驱动（Boids 群体、蚁群信息素、遗传进化…），可解释、可预测、可利用 |
| 多人手感 | 延迟补偿 + 插值平滑 | **不补偿**；延迟 = 惯性 / 质量，成为策略变量 |
| 美术资源 | 大量贴图 | **零图片 / 零图标 / 零外部字体**，Canvas 2D 几何图元 + 单字标记 |
| 可复现 | 随机世界难以复现 | 世界由 `seed` 完全决定；同 `seed` + 同指令序列 → 同结果 |

**一句话定位**：在一片由 46 个经典算法共同演化出的荒野里活下去，可以一个人慢慢建，也可以进房间和别人一起撞来撞去。

## 2. 目标用户

| 用户群 | 特征 | 核心诉求 |
| --- | --- | --- |
| 主要：喜欢算法 / 编程的玩家（18–35 岁） | 听说过生命游戏、Boids、蚁群、遗传算法 | 想在游戏里**看见算法长出东西**：滑翔机、蚁道、火蔓延，并**利用**它们 |
| 次要：生存建造 / 经营玩家 | 喜欢采集—建造—科技循环 | 有长期目标（时代跃迁、基地规模、排行榜） |
| 长尾：联机社交玩家 | 通过链接进房间 | 实时同图协作 / 互相冲撞，无需安装客户端 |

## 3. 核心价值

1. **算法长出世界**：地形、生态、火焰、植物、兽群全部由内核演化，玩家在「理解法则」中获得乐趣。
2. **涌现可被利用**：滑翔机可捕获为移动信标；蚁道可引导搬运货物；火可用来开荒；结晶可采集；守卫走法可预测因而可设计陷阱。
3. **延迟即玩法**：联机时不测 ping、不插值，网络质量变成「球有多重」，形成全新手感与策略。
4. **永不卡死**：内核硬上限 + tick 超时保护 + 异常降级 no-op，50ms 预算内必然完成一个 tick。
5. **零资源秒开**：纯几何绘制 + 无构建工具。

- **阵营对抗 / PVP 计分 / 自走棋对战**（主体是生存建造）

### 5.4 MVP 范围定义（**算法层分批上线**）

**MVP = 全部 P0（F-01 ~ F-22）**，其中算法层按下列批次落地，Agent2 必须按顺序交付：

| 批次 | 算法层 | 内核 | 交付标准 |
| --- | --- | --- | --- |
| **第 1 批（基础）** | 地形与空间 | `value_noise`、`voronoi_grid`、`quadtree`、`bfs`、`astar`、`flow_field`、`bresenham`、`raycast` | 世界能生成、实体能寻路与碰撞 |
| **第 2 批（世界法则）** | 元胞与物理 | `conway`、`rule110`、`falling_sand`、`elastic_collision`、`union_find`、`mst_prim`、`mst_kruskal` | 生命层演化、水沙火流动、碰撞生效 |
| **第 3 批（生态涌现）** | 群体智能 | `boids`、`pso`、`aco`、`dbscan`、`food_chain`、`lsystem`、`markov_chain`、`pid` | 14 种涌现单位中的 10 种可用 |
| **第 4 批（文明发展）** | 科技与调度 | `tech_tree`、`topo_sort`、`pagerank`、`priority_queue`、`queue_cooling`、`kalman`、`task_assign`、`dijkstra`、`mc_build` | 科技树、建造队列、NPC 搬运可用 |

> **留待扩展（MVP 只做最小可玩版本）**：`genetic` 多代抗性（F-27）、Voronoi 多方领地 UI（F-26）、`minimax_ab` 深度守卫（MVP 用 `xiangqi_moves` 的确定性走法即可）。

**MVP 验收链路**：陌生人打开链接 → 注册 → 创建世界（随机 seed）→ 进入 → 采集木头/石头 → 建造墙与农场 → 研究 3 个科技 → 熬过第 1 个夜晚（看到火蔓延或流萤飞过）→ 保存退出 → 重新进入进度仍在 → 结束一局 → 在总榜看到自己 → 另开一个浏览器进入同一房间，两人相撞并互相撞飞。这条链路跑通即 MVP 完成。

## 6. 非功能需求

### 6.1 稳定性（**第一优先级**）

| 项 | 硬性要求 |
| --- | --- |
| 内核有界 | 每个内核核心逻辑 **≤15 行**；所有循环 / 递归带硬上限参数（`maxNodes` / `maxIter` / `maxDepth` / `maxGen` …） |
| **tick 预算** | 单 tick ≤ **50ms**（20 TPS）；各阶段预算见 SDD §4.2；**任一段超时即降级**（跳过该段非关键更新并记录 `tickDegraded`） |
| 世界分区轮转 | 96×96 划分为 **16×16 的 36 个区块**；元胞层 / 生态层每 tick 只更新 **1/4 区块**（轮转），保证预算 |
| 实体上限 | 同世界实体总数 `MAX_ENTITIES = 512`（含玩家、涌现单位、投射物）；超上限时 `food_chain` 抑制刷新 |
| 不死循环 | 世界 tick 无终止概念（持续运行），但**每个内核调用必然在硬上限内返回**；`simulateTick` 外层包 `try/catch` + 超时计数器 |
| 结果可复现 | 唯一随机源为注入的 `mulberry32` rng；引擎与内核内**禁止** `Math.random()`、`Date.now()`；时间由 `world.tick` 驱动 |
| 异常隔离 | 任一内核或阶段抛错 → 捕获、记 `error` 事件、该阶段降级为 **no-op**，世界继续 |
| 指令安全 | 客户端指令服务端二次校验（坐标、资源、冷却、距离）；非法指令丢弃并回 `error`，**不回滚世界** |

### 6.2 性能

| 项 | 指标 |
| --- | --- |
| 单 tick 计算 | ≤ 50ms（典型 ≤ 15ms） |
| 单世界内存 | ≤ 64MB |
| 广播 | `delta` 10Hz，单包 ≤ 32KB；`snapshot` 每 5s，单包 ≤ 512KB |
| 接口响应 | P0 接口 P95 ≤ 150ms（本地 SQLite，1 万条 scores） |
| 落盘 | 每 100 tick（5s）增量落盘一次；世界关闭时全量落盘 |
| 首屏加载 | ≤ 2s；静态资源总量 ≤ 150KB；无外部 CDN |
| 渲染帧率 | 客户端 60 FPS；逻辑不跑在前端 |
| 并发 | 单进程 ≥ 8 个活跃房间 × 8 人；≥ 200 个 WebSocket 连接 |

### 6.4 安全

| 威胁 | 要求 |
| --- | --- |
| 弱密码 | 8–64 字符，必须同时含字母与数字；12 个常见弱密码黑名单 |
| 密码存储 | bcryptjs cost = 10；**任何响应不得返回 `password_hash`** |
| 暴力破解 | 登录：同 IP + 用户名每 5 分钟 ≤ 10 次；注册：同 IP 每小时 ≤ 10 次；超出 429 |
| 令牌 | JWT HS256，7 天；登出通过 `token_version` 递增立即失效；签名错 / 过期 / 被登出分别返回不同错误码 |
| **WS 鉴权** | 连接后 **5 秒内必须发送 `hello`**（带 Bearer token），否则服务端主动关闭（4001）；未 `hello` 前任何 `intent` 一律丢弃 |
| **指令限流** | 单连接 ≤ 30 条 `intent` / 秒；超出丢弃并回 `error/2005`；**不做 RTT 测量** |
| 刷分 | **不存在任何「提交分数」接口**；分数由服务端从世界状态计算 |
| 作弊 | 世界全在服务端；客户端只能发 5 类指令（`move`/`gather`/`build`/`attack`/`drop`），服务端二次校验 |
| XSS | 用户可控文本一律 `textContent`；CSP；用户名规则从源头阻断 `<script>` |
| SQL 注入 | 全部预编译 `?` 位置参数 |
| 请求体 | `express.json({ limit: '1mb' })`，超出 413；WS 单帧 > 64KB 直接关闭（4003） |

### 6.5 可用性

| 项 | 要求 |
| --- | --- |
| 错误提示 | 所有失败有中文可读提示；不暴露堆栈 |
| 令牌过期 | 任意接口 401 → 清空凭据 → 回登录视图 → 提示「登录已过期」；WS 关闭码 4001 → 提示重连 |
| 断网 / 断线 | WS 断开显示「连接中断，正在重连…」；**60 秒内重连恢复同一 `playerId` 与状态**；超过 60 秒房间内实体转为「离线化身」（保留可被撞飞的刚体） |
| 登录态保持 | 令牌存 `sessionStorage`；刷新保持登录 |
| 中途离开 | 世界在服务端持续运行（无玩家时 tick 降频至 2 TPS，仍演化） |
| 可运维 | 启动日志打印端口、DB 路径、DB 驱动、已加载内核数 / 涌现单位数；`/api/health` 可探活 |

## 8. 关键指标（上线后观察，不作 MVP 门槛）

- 访问 → 注册转化 ≥ 20%
- 人均创建世界数 / 日 ≥ 1.5；人均在线时长 ≥ 12 分钟
- 联机房间占比（目标 ≥ 30% 的局有 2 人以上）
- 平均存活天数（期望 5–20 天；< 3 天说明生存压力过强）
- 14 种涌现单位的「被玩家利用」事件触发分布（用于平衡）
- tick 降级率（期望 < 1%）
